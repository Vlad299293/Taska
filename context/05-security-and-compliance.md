# 05-security-and-compliance.md

## Модель безопасности

### 1. Аутентификация
- Используется Supabase Auth (Email/Password).
- Сессии управляются через JWT, которые автоматически прикрепляются к запросам Supabase Client.

### 2. Авторизация (RLS)
Система использует **Row Level Security (RLS)** на уровне PostgreSQL. 
- Доступ к любой записи (`Workspace`, `Task`, `Session`) разрешен только если пользователь является членом связанного воркспейса.
- Проверка членства реализована через функцию `private.is_member(workspace_id)`.
- Функция `is_member` помечена как `security definer` и работает в схеме `private`, недоступной напрямую извне.

### 3. Валидация данных
- **На уровне БД**: Используются `CHECK` констрейнты:
    - `title`: длина от 1 до 120 символов.
    - `estimate_min`: от 5 до 600, кратно 5.
    - `priority`: только 'high', 'medium', 'low'.
    - `status`: только 'backlog', 'in_progress', 'paused', 'done'.
- **На уровне приложения**: Валидация форм перед отправкой (например, проверка уникальности никнейма).

### 4. Конфиденциальность
- Личные данные пользователей хранятся в схеме `auth` (управляется Supabase).
- Публичные данные (никнеймы) доступны для проверки при регистрации.
