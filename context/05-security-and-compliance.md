# 05-security-and-compliance.md

## Модель безопасности

### 1. Аутентификация
- Локальные профили в SQLite (почта/никнейм + пароль). Пароль хранится как PBKDF2-SHA256 (600 000 итераций, соль на пользователя).
- Сообщение об ошибке входа одинаково для «нет пользователя» и «неверный пароль».
- Вошедший пользователь запоминается в `localStorage` (только id, без пароля).

### 2. Изоляция данных
- Приложение однопользовательское на устройстве; все данные принадлежат рабочему пространству профиля, запросы фильтруются по `workspace_id`.
- Файл базы не шифруется: защита данных обеспечивается учётной записью ОС. Шифрование — возможное будущее требование.
- CSP запрещает любые внешние запросы.

### 3. Валидация данных
- **На уровне БД (SQLite)**: Используются `CHECK` констрейнты:
    - `title`: длина от 1 до 120 символов.
    - `estimate_min`: от 5 до 600, кратно 5.
    - `priority`: только 'high', 'medium', 'low'.
    - `status`: только 'backlog', 'in_progress', 'paused', 'done'.
- **На уровне приложения**: Валидация форм перед отправкой (например, проверка уникальности никнейма).

### 4. Конфиденциальность
- Данные не покидают компьютер пользователя.
