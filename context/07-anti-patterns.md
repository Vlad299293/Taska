# 07-anti-patterns.md

## Что мы НЕ делаем в Taska

### 1. Бизнес-логика на фронтенде
- **НЕЛЬЗЯ**: Рассчитывать итоговое потраченное время задачи на клиенте и отправлять `UPDATE` в БД.
- **НУЖНО**: Вызывать RPC функцию `complete_block`, которая делает расчет на стороне сервера. Это предотвращает подмену данных и ошибки синхронизации.

### 2. Прямой доступ к данным без RLS
- **НЕЛЬЗЯ**: Отключать RLS для удобства разработки.
- **НУЖНО**: Всегда описывать политики `POLICY` для каждой таблицы.

### 3. Сложные зависимости в UI
- **НЕЛЬЗЯ**: Создавать глубоко вложенные цепочки компонентов с передачей стейта через 5+ уровней (Prop Drilling).
- **НУЖНО**: Использовать композицию компонентов или контекст (если потребуется масштабирование).

### 4. Игнорирование ошибок БД
- **НЕЛЬЗЯ**: Оборачивать вызовы БД в пустые `try-catch` блоки.
- **НУЖНО**: Обрабатывать ошибки валидации (CHECK constraints) и выводить пользователю понятные сообщения.
